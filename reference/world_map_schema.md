# `world_map.yaml` schema

`world_map.yaml` describes a Civilization-style world map of the real Earth. Each tile covers
**0.5° of latitude × 0.5° of longitude**, giving a grid of **720 columns × 360 rows = 259,200 tiles**.
For each tile the file stores its landform (`terrain`) and what is on its land (`cover`) as two
separate sets of percentages, whether it has a river, and links to its eight
neighbours. It also lists 51 navigable rivers with the tiles each one runs through.

The grid itself is defined in `grid.py`, which every script and the server share. The file is
generated by `gen_map.py` (with `etopo_blocks.py`) from the datasets in `data/`; see
`world_map_generation.md`. Don't edit it by hand: change the generator and rerun `python gen_map.py`.
`python validate_map.py` checks every guarantee in section 6. `python convert_map.py` writes a faster-
loading columnar copy, `world_map.json` (section 8).

---

## 1. Top-level structure

```yaml
map:     { ... }   # grid metadata and data sources
rivers:  { ... }   # 51 navigable rivers
tiles:   { ... }   # 259,200 tiles, keyed by tile id
```

The file begins with a few `#` comment lines that summarise how it was made. Parsers can ignore them.

---

## 2. Conventions

### 2.1 Coordinates
- Latitude runs from **-90 (south) to +90 (north)**. Longitude runs from **-180 (west) to +180 (east)**.
- All coordinates are decimal degrees on the WGS84 globe.

### 2.2 Tile ids
A tile id names the tile's **south-west corner**, in **tenths of a degree**:

```
<N|S><|lat| x 10 as 3 digits><E|W><|lon| x 10 as 4 digits>
```

| id          | south-west corner    | covers |
|-------------|----------------------|--------|
| `N395W1055` | lat 39.5, lon -105.5 | 39.5°N–40.0°N, 105.5°W–105.0°W |
| `N000E0000` | lat 0.0, lon 0.0     | 0°–0.5°N, 0°–0.5°E |
| `S005W0005` | lat -0.5, lon -0.5   | 0.5°S–0°, 0.5°W–0° |
| `S900W1800` | lat -90.0, lon -180.0 | the tile in the far south-west corner |
| `N895E1795` | lat 89.5, lon 179.5  | the tile in the far north-east corner |

- Latitude 0 counts as `N`, so there is **no `S000`**. Likewise longitude 0 is `E`, so there is **no `W0000`**.
- The corner's latitude runs from -90.0 to 89.5 and its longitude from -180.0 to 179.5, in steps of 0.5.
- Regex: `^[NS]\d{3}[EW]\d{4}$`

Converting between an id and its corner (Python; the same code is in `grid.py`):

```python
import math

def tile_id(lat: float, lon: float) -> str:      # corner: lat in -90.0..89.5, lon in -180.0..179.5
    la, lo = round(lat * 10), round(lon * 10)
    return f"{'N' if la >= 0 else 'S'}{abs(la):03d}{'E' if lo >= 0 else 'W'}{abs(lo):04d}"

def parse_tile_id(tid: str) -> tuple[float, float]:  # -> (lat, lon) of the south-west corner
    lat = int(tid[1:4]) / 10 * (1 if tid[0] == 'N' else -1)
    lon = int(tid[5:9]) / 10 * (1 if tid[4] == 'E' else -1)
    return lat, lon

def tile_at(lat: float, lon: float) -> str:      # id of the tile containing any point
    row = min(359, max(0, 359 - math.floor((lat + 90) * 2)))
    col = math.floor((lon + 180) * 2) % 720
    return tile_id(89.5 - 0.5 * row, 0.5 * col - 180)
```

A tile covers `[lat, lat + 0.5)` × `[lon, lon + 0.5)`, so a point exactly on a boundary belongs to
the tile north or east of it: `tile_at(0, 0)` is `N000E0000`.

### 2.3 Grid indexing and order
To store tiles in a 2-D array, use row 0 = northernmost and column 0 = westernmost:

```
row = (89.5 - lat) * 2      # 0..359
col = (lon + 180) * 2       # 0..719
index = row * 720 + col     # flat index, 0..259,199
```

Tiles appear in the file in that order: row by row from north to south, and from west to east within
each row. So the first tile is `N895W1800` and the last is `S900E1795`.

### 2.4 Wrapping
- **East–west wraps around:** the tile east of longitude 179.5 is longitude -180.0, and vice versa.
- **North–south does not wrap:** tiles in the top row (lat 89.5) have no `n`, `ne` or `nw` neighbour,
  and tiles in the bottom row (lat -90.0) have no `s`, `se` or `sw` neighbour. Those links are `null`.

## 3. `map` section

| key | type | value / meaning |
|-----|------|-----------------|
| `projection` | string | `equirectangular`. The grid is evenly spaced in latitude and longitude. |
| `tile_size_degrees` | float | `0.5` |
| `width` | int | `720` (columns) |
| `height` | int | `360` (rows) |
| `tile_id_format` | string | A one-line description of the id format in 2.2. |
| `wraps_east_west` | bool | `true` |
| `wraps_north_south` | bool | `false` |
| `source_image` | string | `bmng_200407_8192x4096.jpg`: an 8192×4096 copy of the satellite image the terrain was read from. It is also the globe texture used by `server.py`. |
| `terrain_types` | list of strings | `[water, plains, hills, mountains]`: the keys of every tile's `terrain` (landform) mapping, in this order. |
| `cover_types` | list of strings | `[grass, forest, desert, sand, wetlands, tundra, ice]`: the keys of every tile's `cover` mapping, in this order. |
| `sources` | mapping, name → URL | Where each input dataset was downloaded from. Keys: `satellite_image`, `elevation`, `glaciers`, `ice_shelves`, `sea_ice` (Arctic), `sea_ice_south`, `rivers`, `wetlands`, and `navigable_rivers` (the Wikipedia list). `data/SOURCES.txt` has fuller descriptions. |

## 4. `rivers` section

A mapping from **river name** to river record. The map keeps only **navigable rivers**: the 51 rivers
on Wikipedia's [List of waterways](https://en.wikipedia.org/wiki/List_of_waterways) that Natural
Earth's 1:10m river layer draws. Names are the list's English names, double-quoted (`"Amazon"`,
`"Yellow"`, `"Dnieper"`, `"Rhône"`). Rivers are ordered by `scalerank`, then by name.

```yaml
rivers:
  "Nile":
    scalerank: 1
    natural_earth_rivernum: [4, 5, 9, 14, 16, 17]
    natural_earth_names: ["Nile", "El Bahr el Abyad", "Bahr el Jebel", "Albert Nile", "Victoria Nile"]
    wikipedia: https://en.wikipedia.org/wiki/Nile_River
    tiles: [N235E0325, N240E0325, N245E0325, ...]
    segments:
      - [N235E0325, N240E0325, N245E0325, ...]
```

| key | type | meaning |
|-----|------|---------|
| `scalerank` | int 0–10 | Natural Earth's importance rank: 0–2 = the largest rivers, 9–10 = minor ones. This is the lowest (most important) rank among the river's pieces. |
| `natural_earth_rivernum` | list of ints | Natural Earth `rivernum` ids of the pieces merged into this river. |
| `natural_earth_names` | list of strings | The Natural Earth river names merged into this river. Natural Earth often uses local names or splits a river: the Nile above Aswan is "El Bahr el Abyad", "Bahr el Jebel" and so on; the Danube's upper course is "Donau". |
| `wikipedia` | string (URL) | The article the List of waterways links for this river. |
| `tiles` | list of tile ids | Every tile the river passes through, **each listed once**, in the order first reached while walking the segments. |
| `segments` | list of lists of tile ids | The river's course as one or more **continuous chains** (one per Natural Earth line), in the source's drawing order. That is usually, but not always, downstream. Consecutive tiles in a chain always share an edge or corner. A chain can revisit a tile if the river bends back into it. Use `segments` to draw the river; use `tiles` for lookups. |

Notes:
- Rivers can share tiles where they meet. A tile's `rivers` lists every river in it.
- Some listed rivers are only partly drawn by Natural Earth. The St. Lawrence covers only its upper
  course near Lake Ontario (5 tiles), and the Amazon starts at the Ucayali/Marañón confluence in Peru.
- `gen_map.py` can instead keep every Natural Earth river (1,110 rivers, 13,824 tiles) by setting
  `NAVIGABLE_ONLY = False`. Those rivers are then named as Natural Earth spells them, and unconnected
  rivers that share a name get a country code: `"Colorado (USA)"`, `"Colorado (ARG)"`. In that mode
  `natural_earth_names` and `wikipedia` are absent.

## 5. `tiles` section

A mapping from **tile id** to tile record. All 259,200 ids appear exactly once.

```yaml
tiles:
  N480E0160:                 # Vienna
    lat: 48.0
    lon: 16.0
    center: [48.25, 16.25]
    terrain: {water: 0, plains: 28, hills: 72, mountains: 0}
    cover: {grass: 69, forest: 30, desert: 0, sand: 0, wetlands: 1, tundra: 0, ice: 0}
    river: true
    rivers: ["Danube"]
    neighbors: {n: N485E0160, ne: N485E0165, e: N480E0165, se: N475E0165, s: N475E0160, sw: N475E0155, w: N480E0155, nw: N485E0155}
```

| key | type | meaning |
|-----|------|---------|
| `lat` | float | Latitude of the south-west corner, -90.0..89.5, always written with one decimal. The tile spans `lat` to `lat + 0.5`. |
| `lon` | float | Longitude of the south-west corner, -180.0..179.5, always written with one decimal. The tile spans `lon` to `lon + 0.5`. |
| `center` | `[float, float]` | `[lat + 0.25, lon + 0.25]`, written with two decimals |
| `terrain` | mapping, landform type → int | The landform: share of the **whole tile** that is water, plains, hills or mountains, in percent. See 5.1. |
| `cover` | mapping, cover type → int | What is on the tile's **land** (its plains + hills + mountains): share that is grass, forest, desert, sand, wetlands or tundra, in percent. See 5.2. |
| `river` | bool | `true` if at least one river's `tiles` list includes this tile. |
| `rivers` | list of strings | **Only present when `river` is `true`.** Names of the rivers in this tile, each a key in the `rivers` section, in `rivers` section order. |
| `neighbors` | mapping, direction → tile id or `null` | The eight neighbours. See 5.3. |

### 5.1 `terrain`: the landform
- Always has all four keys from `map.terrain_types`, in that order: `water, plains, hills, mountains`.
- Values are integers from 0 to 100, and **they always add up to exactly 100**.
- Values are shares of the whole tile's area (144 sample pixels of 2.5 arc-minutes each). A tile can
  be, for example, 60% plains, 30% hills and 10% water.

Each sample pixel gets exactly one landform. The first rule that applies wins:

| order | type | rule |
|-------|------|------|
| 1 | `water` | Antarctic ice shelves (floating ice); otherwise ocean, sea or lake colour in the satellite image, unless the pixel is inside a glacier outline. Sea ice is water. |
| 2 | `mountains` | Land with ≥ 500 m of elevation relief within its ~9 km block (ETOPO1). |
| 3 | `hills` | Land with 100–499 m of relief. |
| 4 | `plains` | Land with less than 100 m of relief. |

Ice is not a landform; it is cover (5.2). Land under glaciers and ice sheets gets the landform of the
ice surface, which ETOPO1's "ice surface" version gives. So the Greenland and Antarctic interiors are
plains, and the Transantarctic Mountains are hills and mountains.

Ocean beyond the coast counts as sea level (0 m) when measuring relief. So a low coastline never
reads as hills, while a genuinely high coast (fjords, sea cliffs) still does.

### 5.2 `cover`: what is on it
- Always has all seven keys from `map.cover_types`, in that order:
  `grass, forest, desert, sand, wetlands, tundra, ice`.
- Values are shares of the tile's **covered surface**: its land (`plains + hills + mountains`) plus
  any **frozen water** (sea ice and ice shelves, which are `water` in `terrain`). They are not shares
  of the whole tile. Example: a tile that is 50% water and 50% plains, with `cover: {forest: 100, ...}`,
  is half open sea and half forested plain.
- Values are integers from 0 to 100:
  - **With land** (`plains + hills + mountains` above 0), they add up to exactly 100.
  - **With no land,** they are either all 0 (open sea) or `ice: 100` and nothing else (frozen sea or an
    ice shelf).
- Cover isn't broken down by landform. A tile that is 50% hills and 50% plains with 50% forest doesn't
  say whether the forest is on the hills or the plains; assume it is spread evenly.

Each land or frozen-water pixel's cover comes from these rules, in order:

| order | type | rule |
|-------|------|------|
| 1 | `ice` | Floating ice: an Antarctic ice shelf (Natural Earth), or water inside the sea ice that survived the summer minimum (NSIDC: Arctic September 2025, Antarctic February 2025). Ice on land: inside a glacier, ice cap or ice sheet outline (Natural Earth), or white in the image in the northern hemisphere or from 60°S poleward, where white is permanent snow or ice. |
| 2 | `tundra` | Land under southern-hemisphere winter snow (north of 60°S). |
| 3 | `sand` | Flat coastal land below 60° latitude: a plains pixel that touches water, whose block reaches sea level, whose highest point is ≤ 30 m, and that isn't forest. Beaches, dunes and coastal flats. |
| 4 | `tundra` | Grass-coloured land above the tree line (alpine tundra). The tree line is about 4,000 m up to 20° latitude, falling about 70 m per degree poleward. |
| 5 | `desert` / `forest` / `tundra` / `grass` | From colour: tan/red arid land is `desert`; dark green is `forest`; other land at 62° latitude or more is `tundra`; everything else is `grass` (grassland, farmland, savanna). |
| then | `wetlands` | For land without ice: the pixel's wetland share from GLWD v2 (vegetated wetlands where water stands: marshes, flooded forest, peat bogs, mangroves, deltas) is moved to `wetlands`, and the rest stays with the type above. |

### 5.3 `neighbors`
- Keys, always in this order: `n, ne, e, se, s, sw, w, nw`.
- Each value is a tile id, or `null` past the poles (see 2.4).
- How each direction offsets the tile's (lat, lon), in degrees:

  | dir | Δlat | Δlon |   | dir | Δlat | Δlon |
  |-----|------|------|---|-----|------|------|
  | `n`  | +0.5 | 0    |   | `s`  | -0.5 | 0    |
  | `ne` | +0.5 | +0.5 |   | `sw` | -0.5 | -0.5 |
  | `e`  | 0    | +0.5 |   | `w`  | 0    | -0.5 |
  | `se` | -0.5 | +0.5 |   | `nw` | +0.5 | -0.5 |

  Longitude wraps: `lon' = (lon + Δlon + 180) mod 360 - 180`. `grid.neighbors(row, col)` computes them.
- Links are symmetric: if A's `e` is B, then B's `w` is A, and so on for every direction.
- Top and bottom row tiles have 5 neighbours; every other tile has 8.

## 6. Guaranteed properties

Programs can rely on all of the following. `validate_map.py` checks them.

1. Exactly 259,200 tiles, one for every (lat, lon) with lat in -90.0..89.5 and lon in -180.0..179.5
   (steps of 0.5), in the order given in 2.3.
2. Each tile id matches its `lat`/`lon` according to 2.2.
3. `terrain` has all four keys in `map.terrain_types` order, each 0–100, and they add up to 100.
   `cover` has all seven keys in `map.cover_types` order, each 0–100. They add up to 100 when
   `plains + hills + mountains` is above 0; otherwise they are all 0 or exactly `ice: 100`.
4. Every non-null neighbour id is an existing tile, and links are symmetric.
5. `river` is `true` exactly when the tile appears in some river's `tiles`. In that case `rivers`
   lists exactly those rivers.
6. Every name in a tile's `rivers` is a key in the top-level `rivers` section.
7. A river's `tiles` has no duplicates and equals the set of tiles in its `segments`. Consecutive
   tiles within a segment are different and adjacent (sharing an edge or a corner, with east–west
   wrapping).
8. `world_population.yaml` lists the same tiles in the same order with the same `neighbors`.

## 7. YAML notes and loading

- Plain YAML 1.1/1.2: block mappings, with flow-style `{...}` and `[...]` for short records, and a
  block sequence for `segments`. It uses no anchors, aliases or custom tags.
- `null`, `true` and `false` are the only special scalars. Tile ids are unquoted plain scalars. River
  names are double-quoted, with `\"` and `\\` escapes.
- UTF-8 encoding with LF line endings. The file is about **87 MB** and takes about 70 s to parse even
  with PyYAML's C loader, so programs that load it often should use `world_map.json` (section 8).
  If you do read the YAML, use a C-accelerated loader if you can:

```python
import yaml
try:
    Loader = yaml.CSafeLoader
except AttributeError:
    Loader = yaml.SafeLoader

with open("world_map.yaml", encoding="utf-8") as f:
    world = yaml.load(f, Loader=Loader)

tile = world["tiles"]["N275E0865"]                           # Everest
print(tile["terrain"]["mountains"])                          # 56
east = world["tiles"][tile["neighbors"]["e"]]                # follow a link
nile_tiles = world["rivers"]["Nile"]["tiles"]
```

- For a dense 2-D grid, place each tile at `grid[round((89.5 - lat) * 2)][round((lon + 180) * 2)]`
  (see 2.3), or use `grid.row_col(lat, lon)`.

## 8. `world_map.json`: the same data, columnar

`convert_map.py` turns the YAML into `world_map.json` (about 6.5 MB, about 0.3 s to load), which is
what `server.py` reads. It verifies that the JSON reproduces every tile and river of the YAML exactly.

```json
{ "format": "world_map/columnar-2",
  "map": { ... },
  "order": "index i -> row i//720, col i%720; south-west corner lat = 89.5 - 0.5*row, lon = 0.5*col - 180",
  "rivers": { "Nile": {"scalerank": 1, "natural_earth_rivernum": [...], "natural_earth_names": [...],
                        "wikipedia": "...", "tiles": [...], "segments": [[...]]}, ... },
  "terrain": { "water": [100, ...], "plains": [...], "hills": [...], "mountains": [...] },
  "cover": { "grass": [0, ...], "forest": [...], ..., "ice": [...] } }
```

- `map` and `rivers` are the YAML's sections, unchanged.
- `terrain` and `cover` have one array per type, in `map.terrain_types` / `map.cover_types` order, each
  with 259,200 percentages in flat-index order (2.3). Tile i's `terrain` is `{type: terrain[type][i]}`,
  and likewise for `cover`.
- The format id was `world_map/columnar-1` when terrain was a single set of nine types; readers should
  reject other ids.
- Nothing else is stored, because it follows from the index or the rivers:
  - `lat`, `lon`, `center` and `neighbors` come from the index (`grid.corner()`, `grid.neighbors()`);
  - a tile's `rivers` are the rivers whose `tiles` include it, in `rivers` order, and `river` is
    whether there are any.
- In Python, `convert_map.read_map(path)` returns a `MapColumns` whose `.tile(i)` builds tile i's
  record exactly as in the YAML; `convert_map.load_map(path)` rebuilds the whole YAML structure
  (about 4 s).
